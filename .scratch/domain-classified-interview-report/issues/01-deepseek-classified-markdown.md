# 01: 生成首个 DeepSeek 领域化 Markdown 报告

**What to build:** 打通本地 DeepSeek 配置、面试题分类器和报告生成入口。系统读取完整面经原文，提取并分类真实面试题，生成按固定领域组织的 Markdown；报告包含真实统计、可跳转的来源标题和完整原文附录。建立可替换分类器的最高层测试缝，使核心行为无需访问外部网络即可验证。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 示例配置预留 DeepSeek API key、服务地址、模型名、批次文章数和批次字符数，真实密钥不会进入版本控制或生成产物。
- [ ] API key 为空时，报告生成立即失败并输出清晰的中文错误，不生成伪分类报告。
- [ ] 生产分类器能够向 DeepSeek 提交完整面经原文，并接收可校验的结构化面试题结果。
- [ ] 分类器只提取明确问题或面试任务，允许规范化简写任务，但其契约禁止从普通叙述中生成新问题。
- [ ] 分类结果为每道面试题保留一个主领域、完整领域标签集合和可追溯的面经原文关系。
- [ ] 预设领域及顺序固定为 Java语法、JUC、JVM、消息队列、MySQL、Redis、Spring全家桶、计算机网络、Agent、场景题、其他。
- [ ] Spring 生态问题统一归入“Spring全家桶”，不产生 Spring 子标签。
- [ ] 方案设计、故障排查、容量规划、一致性处理或工程权衡问题以“场景题”为主领域。
- [ ] 无法匹配预设领域的面试题归入末尾的“其他”。
- [ ] 多领域题目只在主领域展示一次，其他领域标签仍保留在分类结果中。
- [ ] 不进行文本或语义去重，相同或相似题目按真实出现次数保留。
- [ ] Markdown 删除现有静态高频考点，改为展示本次分类得到的领域题目数和来源文章数。
- [ ] 每道题只显示可跳转的面经原文标题；链接能到达报告末尾唯一且正确的原文锚点。
- [ ] 所有参与分类的面经原文都完整进入 Markdown 附录，不受旧有文章数量和正文长度限制。
- [ ] 自动化测试从完整报告生成入口提供临时抓取数据和可控假分类器，验证领域顺序、统计、来源跳转、完整附录和失败行为。
