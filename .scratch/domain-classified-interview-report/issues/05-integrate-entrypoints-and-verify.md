# 05: 贯通全部入口并完成端到端验收

**What to build:** 让命令行、一键运行和 MCP 使用同一套 DeepSeek 分类配置与报告行为，并通过完整样例完成 Markdown、HTML、失败路径和浏览器交互验收。用户无论从哪个现有入口生成报告，都获得一致的领域化结果和清晰的配置说明。

**Blocked by:** 02: 可靠分类任意数量的面经原文；04: 支持人工清理并导出清理版报告

**Status:** ready-for-agent

- [ ] 命令行直接生成报告时使用统一的 DeepSeek 配置、动态分批和失败语义。
- [ ] 一键运行流程生成与直接命令行一致的 Markdown 和 HTML。
- [ ] MCP 报告生成与全流程入口使用相同的分类器、配置、错误和输出行为。
- [ ] 现有来源过滤模式继续生效，不因领域分类改变文章收录范围。
- [ ] 示例配置和中文文档说明 API key、服务地址、模型、批次限制、费用与无缓存行为。
- [ ] 文档明确 API key 不得提交，并说明缺失或无效时报告会直接生成失败。
- [ ] 文档说明固定分类体系、场景题优先级、完整原文附录及清理版报告的边界。
- [ ] 完整自动化测试从报告生成入口覆盖正常分类、动态分批、来源跳转、完整原文、无缓存和失败路径。
- [ ] 使用代表性本地样例完成 Markdown 与 HTML 的端到端生成，不需要在测试中访问真实 DeepSeek。
- [ ] 使用真实浏览器完成浅色主题、桌面布局、窄屏布局、折叠原文、删除、撤销和导出烟测。
- [ ] 最终报告中不包含 API key、调试请求体或其他敏感配置。
- [ ] 所有新增注释、错误信息和项目文档使用中文，技术名词保留英文。
