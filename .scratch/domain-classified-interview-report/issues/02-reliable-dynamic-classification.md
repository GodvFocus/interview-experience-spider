# 02: 可靠分类任意数量的面经原文

**What to build:** 让分类流程可以稳定处理数量和长度不固定的面经原文。短文章按限制动态合批，长文章使用完整正文独占批次；请求失败时重试并拆分定位，无法恢复的单篇失败会明确终止整次报告生成。

**Blocked by:** 01: 生成首个 DeepSeek 领域化 Markdown 报告

**Status:** ready-for-agent

- [ ] 默认每批最多包含 5 篇文章，且正文总长度最多为 12,000 个字符，两项限制均可配置。
- [ ] 多篇短文章会在不超过两项限制时合并为一个请求。
- [ ] 单篇文章超过批次字符限制时独占一个批次，传入内容仍是完整正文。
- [ ] 合批文章使用稳定标识与模型结果关联，不会把题目挂到错误的面经原文。
- [ ] 可重试错误、返回格式错误和结果校验失败最多自动重试两次。
- [ ] 整批重试后仍失败时自动拆分批次，以定位具体失败文章。
- [ ] 单篇文章最终失败时终止整次报告生成，并在错误中指出失败文章但不泄露 API key。
- [ ] 鉴权失败等不可恢复错误不会进行无意义的批次拆分。
- [ ] 未知领域名称不会扩展公开分类体系；没有已知领域可用的题目归入“其他”。
- [ ] 分类结果会校验文章映射、问题文本、主领域和领域集合，不接受缺失或互相矛盾的数据。
- [ ] 每次报告生成都会重新调用分类器，不读取或写入分类缓存。
- [ ] 连续生成两次相同报告时，测试能够观察到两次独立分类调用。
- [ ] 自动化测试覆盖文章数上限、字符数上限、长文章、重试成功、拆分成功及单篇最终失败。
