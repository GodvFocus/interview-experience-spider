# 按知识领域分类的面经报告

Status: ready-for-agent

## Problem Statement

当前报告主要按牛客网、小红书等来源平台展示整篇面经，并包含一套写死的“高频考点速查”。备考者无法直接按 Java、JUC、JVM、MySQL、Redis、Agent 等知识领域浏览抓取到的真实面试题，也难以从单道题快速追溯到面经原文。

一篇面经原文通常同时包含多个知识领域的问题，文章级分类会丢失这种多领域信息。现有报告还会限制展示文章数量并截断正文，因此无法为所有分类结果提供完整、可跳转的上下文。报告中的固定考点与实际抓取结果也可能不一致。

用户需要系统使用可配置分类器从完整面经原文中提取面试题、识别领域标签，并在 HTML 与 Markdown 中以相同的领域顺序展示。默认分类器应复用本机 Codex CLI 的 ChatGPT 登录态，以减少额外 API 按量费用；DeepSeek 继续作为可选后端。HTML 还需要具备舒适的固定浅色阅读体验，以及不破坏抓取数据的人工清理能力。

## Solution

报告生成过程在完成现有内容过滤后，把完整面经原文动态分批提交给配置的分类器。默认通过非交互 `codex exec` 使用当前 ChatGPT/Codex 订阅额度；需要 API 服务时可以显式切换到 DeepSeek。分类器只提取原文中明确出现的问题或面试任务，可以把“手撕 LRU”等简写规范为完整问句，但不能根据普通叙述生成原文中不存在的问题。

每道面试题拥有一个主领域和零到多个其他领域标签。报告只在主领域章节展示一次，避免重复；其他领域标签保留在分类数据中。要求方案设计、故障排查、容量规划、一致性处理或工程权衡的问题，以“场景题”为主领域。无法匹配预设领域的题目统一进入末尾的“其他”。

HTML 与 Markdown 都以领域为主体组织内容，并用面经原文标题作为来源标签。点击来源标签可以跳转到报告末尾的完整原文。HTML 中原文默认折叠；Markdown 中原文完整展开。现有写死的高频考点被真实的分类统计和领域导航替代。

HTML 使用固定浅色主题和响应式布局。用户可以从当前页面软删除题目、撤销删除、看到实时更新的统计，并导出固化当前清理结果的独立 HTML；这些操作不修改抓取 JSON、原始报告、Markdown 或面经原文。

## User Stories

1. 作为备考者，我希望报告按固定知识领域展示面试题，以便集中复习某一领域。
2. 作为备考者，我希望 Java 语言基础问题统一进入“Java语法”，以便与并发和虚拟机问题区分。
3. 作为备考者，我希望并发编程问题进入“JUC”，以便集中复习线程、锁、并发容器和线程池。
4. 作为备考者，我希望 JVM 问题独立展示，以便集中复习内存、GC、类加载和故障排查。
5. 作为备考者，我希望消息队列、MySQL、Redis、计算机网络和 Agent 分别形成独立章节，以便快速定位目标知识领域。
6. 作为备考者，我希望 Spring、Spring Boot、Spring MVC 和 Spring Cloud 使用统一的“Spring全家桶”标签，以免同一生态被拆散。
7. 作为备考者，我希望方案设计、故障排查、容量规划、一致性处理和工程权衡问题优先进入“场景题”，以便集中训练开放式工程问题。
8. 作为备考者，我希望不属于任何预设领域的题目进入最后的“其他”章节，以免内容丢失。
9. 作为备考者，我希望分类顺序固定，以便每次生成报告时都能形成稳定的阅读习惯。
10. 作为备考者，我希望一道涉及多个领域的题目只展示一次，以免重复阅读。
11. 作为备考者，我希望系统保留一道题涉及的其他领域标签，以免多领域信息在分类过程中丢失。
12. 作为备考者，我希望题目卡片保持简洁，只显示可以跳转的面经原文标题，而不是堆叠多个领域标签。
13. 作为备考者，我希望点击面经原文标题即可跳转到报告中的完整原文，以便查看问题上下文。
14. 作为备考者，我希望原文处保留外部来源链接，以便需要时打开原始帖子。
15. 作为备考者，我希望分类器使用完整正文提取题目，以免文章后半部分的问题因展示截断而遗漏。
16. 作为备考者，我希望“手撕 LRU”等明确的简写任务能被规范成可读问题，以便分类后的题目表达一致。
17. 作为备考者，我希望系统不从求职感受、教程说明或普通叙述中臆造面试题，以保证内容忠于原文。
18. 作为备考者，我希望不同面经中重复出现的题目暂时全部保留，以便观察真实出现频率和来源。
19. 作为备考者，我希望报告顶部展示各领域题目数量和来源文章数量，以便了解本批面经的知识分布。
20. 作为备考者，我希望 HTML 提供领域目录和快速跳转，以便在长报告中迅速切换章节。
21. 作为备考者，我希望 Markdown 也具有领域目录和原文跳转，以便在支持锚点的 Markdown 阅读器中导航。
22. 作为备考者，我希望 HTML 中的完整原文默认折叠，以免附录干扰主要复习流程。
23. 作为备考者，我希望需要时可以展开任意一篇完整原文，以便核对上下文。
24. 作为备考者，我希望 Markdown 在末尾完整收录所有参与分类的面经原文，以便离线保存全部上下文。
25. 作为备考者，我希望 HTML 使用固定浅色主题、舒适的色彩、行距和内容宽度，以便长时间阅读。
26. 作为使用手机或窄屏设备的备考者，我希望页面布局可以响应屏幕宽度，以便正常阅读和导航。
27. 作为备考者，我希望在 HTML 页面上删除无价值或误提取的题目，以便人工清理报告。
28. 作为备考者，我希望删除是页面内软删除，以免误伤抓取数据和面经原文。
29. 作为备考者，我希望删除后短时间内可以撤销，以便恢复误删题目。
30. 作为备考者，我希望删除题目后领域统计立即更新，以便页面数字与当前可见内容一致。
31. 作为备考者，我希望某个领域的题目全部删除后，该空领域自动隐藏，以免保留空章节。
32. 作为备考者，我希望删除题目不会删除原文附录，以便仍可追溯完整文章。
33. 作为备考者，我希望可以导出清理版 HTML，以便长期保存当前人工清理结果。
34. 作为备考者，我希望清理版 HTML 仍能继续删除题目并再次导出，以便分阶段整理。
35. 作为维护者，我希望导出清理版不会修改原始 HTML、Markdown 或抓取 JSON，以便原始数据始终可恢复。
36. 作为维护者，我希望默认使用本机 Codex CLI 保存的 ChatGPT 登录态，以免为分类另行承担 DeepSeek API 按量费用。
37. 作为维护者，我希望示例配置明确分类器选择、Codex CLI 参数和可选 DeepSeek 参数，以便用户知道如何切换后端。
38. 作为维护者，我希望 Codex 未安装、未登录、额度不可用，或 DeepSeek API key 无效时立即失败并给出明确提示，以免生成看似成功但没有真实分类的报告。
39. 作为维护者，我希望短文章可以合并到同一请求，以减少请求次数。
40. 作为维护者，我希望长文章独占请求且仍使用完整正文，以免为了分批而截断内容。
41. 作为维护者，我希望批量请求失败后能够重试并拆分批次，以便定位具体失败文章。
42. 作为维护者，我希望单篇文章最终仍失败时终止整次报告生成，以免输出不完整且难以察觉的分类报告。
43. 作为维护者，我希望每次生成都重新调用所选分类器，以便报告反映本次模型结果而不是历史缓存。
44. 作为维护者，我希望错误日志指出失败文章，但不泄露 DeepSeek API key 或 Codex 登录凭据，以便安全排查问题。
45. 作为维护者，我希望现有来源过滤逻辑继续生效，以免分类功能改变收录范围的既有语义。

## Implementation Decisions

- 报告生成流程继续以过滤后的牛客网与小红书文章集合为输入；本功能不改变爬取和既有相关性过滤规则。
- 在报告生成领域中使用可替换的面试题分类器接口。生产实现支持 Codex CLI 与 DeepSeek，测试实现可以返回确定性结果或记录请求，不需要访问外部网络。
- `classifier.provider` 默认是 `codex`；分批上限统一放在 `classifier.batch_max_articles` 和 `classifier.batch_max_chars`，并兼容旧版 `deepseek` 中的同名字段。
- Codex 后端使用 `codex exec`、当前 ChatGPT 登录态和订阅额度；运行使用临时会话、临时空目录、只读沙箱与严格 JSON Schema，不授予文件写入或工具执行权限。
- Codex 配置包含 `command`、`model`、`reasoning_effort` 和 `timeout_seconds`。默认按产品要求固定使用 `gpt-5.6-luna`，并将 reasoning effort 设为该模型支持的最高档 `max`；配置仍允许显式覆盖，便于处理账号模型可用性变化。
- DeepSeek 继续使用兼容 OpenAI 的 API。真实 API key 只写入已被 Git 忽略的本地配置；日志、异常和生成产物不得包含 API key 或 Codex 登录凭据。
- Codex CLI 不可用、登录失效、订阅额度不可用，或 DeepSeek API key 无效、服务明确拒绝请求时立即终止生成，并输出中文错误信息。系统不提供规则分类或全部归入“其他”的降级路径。
- 分类器接收完整面经原文，不受旧有正文展示长度配置影响。新报告不再限制每个平台只展示前 30 篇，也不截断附录原文。
- 分类请求按文章长度动态分批。默认每批最多 5 篇，且批内正文总长度最多 12,000 个字符；两个限制都可配置。
- 单篇文章超过批次字符限制时独占一个批次，并继续传入完整正文，不为满足批次限制而截断。
- 每篇文章必须分配稳定的批内标识，模型结果必须携带该标识，以便合并请求后仍能准确关联来源。
- 可重试错误、返回格式错误或结果校验失败时，同一批次最多重试两次。批次仍失败时递归拆分，以定位失败文章；单篇文章最终失败则终止整次生成。
- 每次报告生成都重新调用所选分类器，不读取或写入分类缓存。
- 分类器返回结构化分类结果。每道题至少包含规范化问题文本、主领域和完整领域标签集合；报告生成侧对结构、文章映射和领域值进行严格校验。
- 分类器只提取原文中明确的问题或面试任务。允许把简写任务规范成完整问句，但不得从经验叙述、教程内容或概括性描述中生成新问题。
- 预设领域及顺序固定为：Java语法、JUC、JVM、消息队列、MySQL、Redis、Spring全家桶、计算机网络、Agent、场景题。无法匹配这些领域的题目归入“其他”，“其他”固定排在最后。
- Spring、Spring Boot、Spring MVC 和 Spring Cloud 不产生子标签，统一使用“Spring全家桶”。
- 方案设计、故障排查、容量规划、一致性处理和工程权衡问题以“场景题”为主领域；具体技术可以保留为其他领域标签。
- 每道题只能有一个主领域，可以有多个领域标签。题目只在主领域章节渲染一次，其他标签不导致重复展示。
- 模型返回未知领域名称时，该名称不进入公开分类体系；没有任何已知领域可用的题目归入“其他”。
- 首版不进行文本或语义去重。相同或近似题目按原始出现次数分别保留，并各自保持来源关系。
- 分类结果中的每道题保留来源文章标识、面经原文标题、原始外部链接和报告内原文锚点。平台信息继续保留在文章元数据中，但题目卡片不显示平台标签。
- 题目卡片只显示一个以面经原文标题命名的来源标签。点击该标签跳转到报告末尾对应的完整原文。
- 现有静态“高频考点速查”被移除，替换为基于本次分类结果计算的领域目录、题目数量和来源文章数量。
- HTML 与 Markdown 使用相同的领域顺序、题目集合、来源关系和统计口径。
- HTML 使用固定浅色主题。页面应具备清晰的视觉层级、舒适的对比度与留白、适合长文阅读的行高和内容宽度，以及响应式导航。
- HTML 的完整原文放在报告末尾，并默认折叠。原文仍包含标题、来源平台和外部链接。
- Markdown 的完整原文放在报告末尾并完整展开。领域目录、题目来源标签和原文之间使用可预测的内部锚点连接。
- 从抓取内容和模型结果进入 HTML 的文本必须进行适当转义或清理，防止不受信任内容破坏页面结构或执行脚本。
- HTML 为每道题提供软删除按钮。软删除只影响当前页面状态，不修改抓取数据、原始生成文件、Markdown 或原文附录。
- 软删除后立即重算可见题目数量和来源文章数量；没有可见题目的领域从导航和正文中隐藏。
- 页面提供短时撤销入口，用于恢复最近删除的题目并同步恢复统计和领域显示。
- 页面提供“导出清理版 HTML”操作。导出文件固化当前已删除题目的状态，不包含已经删除的题目，但保留继续删除、撤销和再次导出的能力。
- 刷新原始生成 HTML 会恢复尚未导出的软删除；跨报告持久化删除记录不属于本功能。
- 导出操作完全在浏览器中完成，不向服务端发送报告内容，也不尝试从静态页面改写本地源文件。
- 领域文档使用已经确定的“面经原文、面试题、来源标签、领域标签、主领域、场景题、其他、清理版报告”等术语。代码注释、错误信息和项目文档使用中文，技术名词保留英文。

## Testing Decisions

- 自动化测试只断言外部可观察行为，不断言提示词文本、私有辅助函数调用次数或内部数据结构的具体组织方式。
- 主要测试缝是完整报告生成入口：测试提供临时牛客网和小红书 JSON、临时配置及可控的分类器假实现，然后检查生成的 Markdown、HTML、错误和请求记录。
- 仓库当前没有既有测试文件或测试框架先例。实现时优先采用 Python 标准库测试能力建立最小测试基础，避免仅为本功能引入重量级测试依赖。
- 正常路径测试应覆盖固定领域顺序、“其他”位于最后、Spring 统一标签、场景题主领域、多领域题目只展示一次、其他领域标签被保留以及重复题目不被合并。
- 提取边界测试应使用包含明确问句、简写面试任务和普通叙述的样例，验证分类器契约只返回允许的题目；测试不评估真实大模型的语言质量。
- 完整性测试应验证所有参与分类的文章都进入原文附录，Markdown 不截断正文，HTML 包含完整正文且默认折叠，不再应用每个平台 30 篇限制。
- 导航测试应验证每个题目的来源标题链接都指向实际存在且唯一的原文锚点，领域目录也指向实际章节。
- 统计测试应验证领域题目数和来源文章数来自真实分类结果，而不是静态常量。
- 配置测试应覆盖默认 Codex 后端、Codex CLI 参数、显式 DeepSeek 后端、空 API key、默认分批上限，以及敏感值不出现在错误信息或报告中。
- 动态分批测试应覆盖多篇短文章合批、达到文章数上限、达到字符数上限、单篇长文章独占批次且正文未截断。
- 失败测试应覆盖批次成功、可重试失败后成功、批次失败后拆分、单篇最终失败导致整次生成失败，以及失败时不留下看似成功的最终报告。
- 无缓存测试应连续生成两次报告，并验证两次都调用分类器。
- 安全测试应使用包含 HTML 标签、脚本片段和特殊字符的标题、问题与原文，验证生成页面不会执行不受信任脚本或破坏 DOM。
- HTML 页面需要一次真实浏览器烟测：删除题目后统计更新，空领域隐藏，撤销恢复，原文不受影响，导出的清理版不含已删除题目，并且可以继续删除和再次导出。
- 响应式与视觉验收通过桌面宽度和窄屏宽度各检查一次，确认固定浅色主题下没有横向溢出、导航遮挡或难以辨认的文本。

## Out of Scope

- 不修改牛客网或小红书爬虫的搜索、抓取和 Cookie 处理逻辑。
- 不提供规则分类器、本地模型或所选分类器不可用时的自动降级分类。
- 不缓存模型分类结果，也不复用上次报告的分类结果。
- 不对相同或近似题目进行语义去重、聚类或自动合并。
- 不让用户自定义领域列表、顺序、领域定义或场景题优先级。
- 不在题目卡片中展示平台标签、主领域标签或其他领域标签。
- 不生成题目答案、知识点讲解、难度评级或复习计划。
- 不提供固定深色主题、主题切换器或跟随系统主题。
- 不从 HTML 永久修改抓取 JSON、Markdown、原始报告或面经原文。
- 不让人工删除记录跨重新生成的报告自动生效。
- 不把静态 HTML 改造成需要常驻后端服务的 Web 应用。
- 不建立新的语义 ADR；当前决定均可通过配置或报告结构调整，尚不满足难以逆转且存在重大架构权衡的条件。

## Further Notes

- 因为每次生成都会重新调用所选分类器，生成时间、订阅额度或 API 费用以及模型结果可能发生波动；动态分批减少请求数量，但不会减少需要处理的正文总量。
- 完整 Markdown 会明显大于当前截断版本，这是保证所有题目都能追溯完整上下文的预期成本。
- Codex 和 DeepSeek 的模型名称及能力可能变化，因此模型配置保持可覆盖；当前 Codex 默认值固定为 `gpt-5.6-luna` 和 `max`，只有显式修改 `codex` 配置时才会覆盖。
- 清理版报告是人工整理后的独立 HTML，不是新的事实来源；抓取 JSON 和原始报告仍是可恢复的基线。
